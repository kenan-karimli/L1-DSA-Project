# CONTRIBUTION.md: Project guide and work split

**Project:** DSA1 Hotel Chain Management, UFAZ 2026-2027 (singly linked lists, C11)
**Team:** Kanan Karimli · Zahranur Gasimzade · Rustam Karimli
**Split:** the module `.c` files, their headers and their tests are divided between the three of us (summary in section 8). `main.c` (menu) and the report are not split yet; we decide them later.

---

## 1. What we are building
A program that manages the customers of a hotel chain, using three nested singly linked lists:

```
T_Hotel ─first→ T_Site(Bordeaux) ──next→ T_Site(Lille) ──next→ NULL     sorted by city, no duplicate city
                     │first
                     └→ T_Client(Dupond,Charles) ──next→ T_Client(Martin,Alain) ──next→ NULL
                                                                         sorted by last name, then first name
```
A text menu (options 1–9) drives everything. A booking file can also be loaded with `processingfile`.

## 3. The headers (all in `include/`)
Every header starts with `#pragma once`. Every module header starts with `#include "tp3.h"`. Each `.c` file includes its own header, plus the headers of the modules it calls (see section 5).

### `tp3.h` (Kanan): constants and structs shared by everyone
```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#define MAX_NAME      50
#define BOOKINGS_FILE "data/bookings.txt"   /* processingfile takes no filename in the statement */

/* strings are heap-allocated with copyString and freed with their node */
typedef struct Client {
    char *last_name;
    char *first_name;
    int age;
    int num_room;
    struct Client *next;
} T_Client;

typedef struct Site {
    char *city;
    int number_clients;
    T_Client *first;
    struct Site *next;
} T_Site;

typedef struct Hotel {
    char *name;
    T_Site *first;
} T_Hotel;

/* our addition for searchClients: points into existing nodes, copies nothing */
typedef struct Result {
    T_Client *client;
    char *city;
    struct Result *next;
} T_Result;
```

### Module headers: prototypes only (`critereaName` is spelled that way in the statement)

## 5. Dependencies between members
| Function | Calls (owner) | Must include |
|---|---|---|
| `createSite`, `createHotel` | `copyString` (Zahranur) | `client.h` |
| `addClient`, `searchClients` | `compareNames` (Zahranur) | `client.h` |
| `deleteSite` (Kanan), `freeHotel` (Rustam) | `freeClients` (Zahranur) | `client.h` |
| `processingfile` | `createClient`, `addClient` (Zahranur); `findSite`, `createSite`, `addSite` (Kanan) | `client.h`, `site.h` |
| menu handlers in `main.c` | all of the above | all module headers |

Nobody waits for anyone: Kanan's first push contains `tp3.h`, all the module headers and every `src/*.c` file with **empty stub bodies** (`return 0;` or `return NULL;`), so `main` builds from day one. Each owner replaces the stubs in their own files only.

## 6. Rules
1. Signatures follow the statement and do not change. If `tp3.h` needs a change, ask Kanan. Each owner edits their own module header.
2. Everyone edits only their own files.
3. Work on `feature/<name>` branches, no direct pushes to `main`. Before a PR, `make test` and `make debug` (AddressSanitizer) must pass. `main` must always build.
4. Every `malloc` has a matching `free`.
5. `display*`, `searchClients` and `processingfile` print by themselves, as the statement requires. `scanf` and the menu stay in `main.c`.
6. Whoever writes a `.c` file also writes its test file (`site.c` → `test_site.c`, and so on).
7. Name every `static` helper with its module prefix (`client_...`, `search_...`, `file_...`), so names never clash between modules.
8. Commit format: `feat: ...`, `fix: ...`, `test: ...`.

## 7. Order of work
1. Kanan: all headers + stubs + `tests/` skeleton → `main`. Everyone pulls.
2. In parallel on their own branches: Zahranur (client and file modules), Kanan (site module), Rustam (hotel and search modules).
3. Merge order: `feature/client-file` → `feature/site-module` → `feature/hotel-search`. `main` must build after each merge.
4. Kanan: run `make debug` and a full manual run with `data/bookings.txt`.
